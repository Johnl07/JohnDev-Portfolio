# Contributing Guidelines

Thank you for contributing to this portfolio project. Please follow these guidelines:

## 1. Branching Strategy
- Always branch off the `main` branch.
- Use descriptive branch names:
  - `feat/feature-name`
  - `fix/bug-fix-name`
  - `docs/documentation-update`
  - `style/design-tweaks`

## 2. Commit Message Convention
We adhere to [Conventional Commits](https://www.conventionalcommits.org/):
- `feat:` Introduces a new feature or section
- `fix:` Fixes a bug or styling glitch
- `docs:` Updates documentation or README
- `style:` Formatting or UI styling changes that do not alter logic
- `refactor:` Code refactoring without changing functionality
- `test:` Adding or updating tests
- `chore:` Maintenance tasks or dependency updates

## 3. Pull Requests
- Open a Pull Request (PR) against `main`.
- Provide a clear description of the changes made and include screenshots if UI elements were modified.
- Obtain review and approval before merging.

## 4. Testing
- Verify all changes locally across major screen sizes (mobile, tablet, desktop).
- Run any automated tests (`npm test` or test verification scripts) before submitting a PR.
